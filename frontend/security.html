🔧 How enforcement is wired into the codebase:
• Frontend: AG.guard({ roles: [...] }) in core.js fires on every page load — wrong role → redirect, not just hidden menu items.
• Backend: Every route is protected by the JWT auth middleware (server/middleware/auth.js). Admin routes also call requireAdmin().
• Vet scoping: GET /api/farm/data cross-checks vetAssignments collection before returning any farm records.
• Marketplace: POST /api/marketplace/purchase requires a valid JWT — unauthenticated requests receive HTTP 401.

Protected REST API Endpoints (Server-Side Enforcement)
All /api/security/* routes enforce RBAC on the Express server — the security module pages are only the UI layer.
GET /api/security/stats — Admin only: system KPIs
GET /api/security/users — Admin only: all user accounts
PATCH /api/security/users/:id/role — Admin only: change user role (audit logged)
PATCH /api/security/users/:id/status — Admin only: activate/suspend (audit logged)
POST /api/security/users/:id/reset-password — Admin only: password reset (audit logged)
DELETE /api/security/users/:id — Admin only: delete account (audit logged)
GET /api/security/audit-logs — Admin only: full tamper-evident audit trail
GET /api/security/farms — Admin only: all registered farms & herds
🚀 To run on a truly separate origin during demonstration:
cd nkeane/security-module && npx serve . -l 8081
Then open http://localhost:8081/security.html — a completely different HTTP origin from http://localhost:4001. The Express server's cors({ origin: true }) config accepts both origins.

!
Art. 5 — Data Processing Principles (Minimisation, Purpose Limitation)
Partial ⚠️
Data minimisation is applied — only essential fields collected at registration and listing. Personal data (name, email) is kept strictly off the blockchain (only SHA-256 hashes on-chain). Gap: No formal data retention schedule or automatic expiry policy is defined.
✔
Art. 6–7 — Lawful Basis & Consent
Compliant ✅
Explicit, unticked consent checkbox is mandatory to complete registration (contractual necessity + legitimate interest). Consent timestamp is stored on the user profile in Firestore.
!
Art. 12–14 — Transparency & Privacy Notice
Partial ⚠️
A plain-language privacy summary is shown on the registration page. This Security Config Module serves as a technical privacy reference. Gap: A formal Privacy Policy document has not been separately published.
✔
Art. 15 — Right of Access
Compliant ✅
The "📥 Export My Data" button calls GET /api/farm/export which returns the full account, farm profile, herd records, and blockchain ledger as a downloadable JSON file within seconds.
!
Art. 16 — Right to Rectification
Partial ⚠️
Herd records (animals, health, breeding, feed, sales) can be corrected via the Farmer Dashboard. Gap: Farm profile name and owner name cannot currently be edited after initial registration — a planned profile-edit form would fully satisfy this article.
✔
Art. 17 — Right to Erasure ("Right to be Forgotten")
Compliant ✅
The "🗑️ Delete Account" button calls DELETE /api/farm/account which permanently removes the user document, farm profile, and farm records from Firestore. The blockchain design ensures no PII is ever written to the ledger — only cryptographic hashes remain which cannot be reverse-engineered.
✔
Art. 20 — Right to Data Portability
Compliant ✅
Machine-readable JSON export is available via the Export button. The AI dataset can also be downloaded as CSV from the AI Dashboard. Data is provided in a commonly used, structured, machine-readable format per Art. 20(1).
!
Art. 25 — Data Protection by Design & by Default
Partial ⚠️
Applied: data minimisation at input, hashes-only on-chain, imported prediction rows stored in Firestore, XSS escaping via AG.esc(), role-based page guards, JWT with 8-hour expiry, bcrypt-12 password hashing, session cleared on logout, Helmet.js HTTP security headers, rate limiting. The browser keeps only the language preference and active login session.
!
Art. 30 — Records of Processing Activities (RoPA)
Partial ⚠️
Every animal, health, breeding, sale, and feed event is sealed with a blockchain anchor creating a de-facto event log. The admin audit trail records every LOGIN, ROLE_CHANGE, ACCOUNT_SUSPENDED, and PASSWORD_RESET with actor, IP, and timestamp. Gap: A formal RoPA document (data controller, purpose, retention periods) has not been produced.
✔
Art. 32 — Security of Processing
Compliant ✅
bcrypt (12 rounds) password hashing, JWT HMAC-SHA256 session tokens (8h expiry), Helmet.js HTTP security headers, rate limiting on auth endpoints (30 req/15 min), CORS configuration, tamper-evident blockchain ledger with Proof-of-Work mining. All sensitive keys stored server-side in .env.
✗
Art. 33–34 — Personal Data Breach Notification
Not Yet ⛔
Blockchain tamper verification can detect data integrity failures. Gap: No automated breach detection pipeline or 72-hour supervisory authority notification mechanism is currently implemented.
✗
Art. 35 — Data Protection Impact Assessment (DPIA)
Not Yet ⛔
Gap: A formal DPIA has not been conducted. Recommended before production deployment given the AI health-risk scoring feature (automated profiling of livestock conditions) and permanent blockchain event logging.
